# Firestore Security Rules 変更案レビュー

更新日: 2026-11-17  
対象ブランチ: integration-development  
対象ファイル: firestore.rules

## 現在の本番ルールで確認した問題

共有いただいた現行ルールは全ドキュメントに対して `allow read, write: if true;` となっている。未ログイン利用者を含め、Firestore全体を読み書きできるため、個人情報・出勤記録・学習情報等を保護できていない。

## このブランチに追加した案

- `students/{uid}`: 本人は自分のプロフィールを取得でき、一覧・他人のプロフィール管理は管理者のみ。
- `attendanceItems`: 本人は自分の記録を読み取り・作成でき、全件管理・更新・削除は管理者のみ。
- `attendanceGroups`, `weeklyShifts`: 管理者のみ。
- `notifications`: 対象ユーザーと管理者が読み取り、作成・更新・削除は管理者のみ。
- `dailyWorkPlans`: ログインユーザーが読み取り、管理者が書き込み。
- `woodGroups`: 一般ユーザーは代表状態・確認状態・更新日時のみ更新可能。まとめ行の作成・削除とその他の変更は管理者のみ。
- `woodItems`: 一般ユーザーは工程・進行・担当者・備考・確認・自分の予約情報など、許可フィールドを更新可能。新規作成・削除は管理者のみ。
- `historyLogs`: ログインユーザーは読み取り可能。本人の `updatedBy` を持つ履歴の作成と、管理者による管理を許可。
- `learningInfos`, `searchDictionary`, `subjectDocuments`: ログインユーザーが読み取り、管理者が書き込み。
- `attendance`: 旧 `user.html` 専用の旧コレクションとして明示的に拒否。
- 上記以外のコレクションは最後のルールで拒否。

管理者判定は `students/{request.auth.uid}.isAdmin == true` のみを使用し、業務上の `role` から管理者権限を推測しない。

## 適用前に必ず確認する点

1. **管理者アカウントの棚卸し**: 現在の管理者のうち `isAdmin: true` が設定されていないアカウントは、この案では管理者機能を使えなくなる。role名からの自動昇格は行わず、UIDと本人を確認したうえで管理者が確定する必要がある。
2. **共有タブレット**: `tablet.html` は画面上のログイン操作を設けず、バックグラウンドの匿名認証と `tabletDevices/{uid}` の許可リストで端末を識別する。通常のログイン後ホーム・共通ナビからはリンクしない。未登録端末は名簿・打刻データへアクセスできない。Firebase匿名認証の有効化と端末登録、RulesのEmulator検証が必要であり、本番適用は未実施。
3. **木材管理の更新権限**: 現在の統合ホームは予約済み木材を読むだけで、木材アイテムのユーザー更新画面・許可フィールド・状態遷移検証はまだ完成していない。そのため案では管理者のみ書き込み可能としている。通常ユーザーの工程更新機能を実装する段階で、許可フィールド・履歴追加・状態遷移を検証するルールに変更する。
4. **遅刻・早退**: `admin_late_early.html` は `weeklyShifts` を参照する一方、週シフト作成画面は `attendanceGroups` と `attendanceItems` を使う。実データと現行運用を確認するまで、両方のコレクションを別々に保持する。
5. **旧画面**: `user.html` の `attendance` コレクションは旧形式であり、この案では拒否する。旧画面を利用中の人がいないことを確認する。
6. **Firestore Rules のOR評価**: 既存の全許可ルールを残したままこの案を追加しても制限されない。適用時は全許可のワイルドカードルールを確実に置き換える必要がある。

## まだ行っていないこと

- Firebase Consoleへのルール反映・デプロイ
- Firestoreのユーザーデータ変更（`isAdmin` の設定を含む）
- データ移行
- 共有タブレットの認証方式変更
- 木材管理のユーザー更新機能実装

## 2026-11-18 追記

このレビュー初版の木材書き込み権限の説明は古くなっている。現在の `firestore.rules` には一般ユーザーによる個別木材の許可フィールド更新が追加されているため、上記の現行ブランチ案の説明を正とする。ただし、Firebase ConsoleへのデプロイやEmulator検証を確認したものではない。

また、`tablet.html` は未ログインで `students`・`attendanceItems` を読み、`attendanceItems` を作成する。現在のRules案では拒否されるため、タブレットを含む運用方式を確定するまで本番適用しない。

2026-11-19に追加した木材予約の所有者限定条件は、共同作業とリーダーによる代理登録を妨げるため、ユーザー確認により撤回した。現在のRules案は従来の一般ユーザー更新条件に戻している。

## 2026-11-19 共有タブレットのアクセス方式更新

共有タブレットの「画面上のログイン不要」を維持しながら、Firestoreを未認証のまま公開しない方式として、Firebase Authenticationの匿名認証＋端末UID許可リストを開発ブランチに追加した。

- tablet.html は起動時に匿名認証を行い、ログイン画面を表示しない。
- tabletDevices/{uid} が存在し、enabled == true の端末だけを許可する。
- 未登録端末はUIDを表示するだけで、名簿・打刻データを読み込まない。
- 匿名認証ユーザーは通常の signedIn() 判定から除外し、登録済みタブレット専用のルール以外では通常ユーザー権限を得ない。
- 登録済みタブレットは students の名簿読み取り、attendanceItems の読み取り、および既存の students/{userId} を対象とする出勤・退勤レコードの作成のみ許可する。
- tabletDevices の登録・変更・削除は管理者のみ。端末本人は自分のUIDドキュメントを取得できる。

初回利用にはFirebase Consoleで匿名認証プロバイダを有効化し、共有タブレットで表示されたUIDを tabletDevices/{uid} に enabled: true で登録する作業が必要。ブラウザのサイトデータ消去等でUIDが変わった場合は再登録する。

この方式は開発ブランチに追加しただけであり、Rulesのコンパイル・Emulator検証・Firebaseへの反映は未実施。本番Rulesへ自動適用していない。また、登録端末は名簿情報全体を読むため、端末の物理的な管理が必要。
