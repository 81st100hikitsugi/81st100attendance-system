# 統合システム QA チェックリスト

更新日: 2026-11-18  
対象ブランチ: `integration-development`

この文書は、統合版をテスト環境で検証する際の確認項目。現時点ではコード確認・静的確認の段階であり、Firebase実機テストや本番適用を実施済みという意味ではない。

## 1. 共通ログイン・権限

- [ ] 一般ユーザーがログインすると `home.html` が開く
- [ ] 管理者も同じ `home.html` が開く
- [ ] `students/{uid}.isAdmin === true` のユーザーだけ管理者メニューが表示される
- [ ] `role` の値だけで管理者権限が付与・剥奪されない
- [ ] 各ページの共通ナビゲーションがスマートフォン・PCで表示される
- [ ] ログアウト後にログイン画面へ戻る

## 2. 共通ホーム

- [ ] 主要ページのHTML内リンク・CSS・JavaScript参照先がリポジトリ内に存在する（2026-11-18時点で主要11ページを静的照合し、参照切れなし）


- [ ] 今日の日付と曜日が表示される
- [ ] 今日の `dailyWorkPlans` が開始時刻順に表示される
- [ ] 自分の `attendanceItems` のうち `state="出勤予定"` の今日のシフトだけが表示される
- [ ] 自分が予約した `woodItems` だけが表示される
- [ ] 予定・シフト・予約がない場合に空状態が表示される
- [ ] 通信断時、端末に保存済みのFirestoreキャッシュがあれば表示される

## 3. 木材管理

- [ ] まとめ行と個別木材の数量が一致する
- [ ] 名称・素材の複数語検索がOR条件として機能する
- [ ] 長さの範囲指定と許容差指定が同時に適用されない
- [ ] 工程・進行・担当者の複数選択が各フィルター内OR、フィルター間ANDになる
- [ ] 備考あり／なしが個別木材とまとめ行の備考を含めて判定される
- [ ] 数量順が個別木材の実数で並び替わる
- [ ] 一般ユーザーは個別木材の状態・担当・備考・確認・予約を更新できる
- [ ] 一般ユーザーはまとめ行の作成・編集・削除ができない
- [ ] 管理者はまとめ行と個別木材を管理できる
- [ ] 一括更新が選択した個別木材だけに適用される
- [ ] 状態・担当・備考の変更が履歴と `historyLogs` に記録される
- [ ] 代表状態・まとめ行チェックが個別木材から再計算される
- [ ] 他ユーザーが予約中の木材を別ユーザーが解除できない
- [ ] オフライン時は編集・予約・一括更新ができず、キャッシュ済みデータは閲覧できる

## 4. 学習情報

- [ ] 管理者ホームから学習データ移行画面へ移動でき、一般ユーザーは移行操作を開始できない


- [ ] 学習情報一覧・教科別一覧・教科資料が表示される
- [ ] 検索辞書の別表記検索が機能する
- [ ] 論理削除された学習情報が通常一覧に表示されない
- [ ] 管理者だけが学習情報・教科資料・検索辞書を編集できる
- [ ] 旧データ移行前にJSONバックアップが保存できる
- [ ] 移行先に同一IDがある場合、コピー全体が中止される
- [ ] 移行後に件数・代表レコード・HTML資料・Timestampを照合する

## 5. 出勤管理・タブレット

- [ ] 既存の `attendanceItems` のシフト予定・打刻履歴が維持される
- [ ] 本人のシフト画面では本人のレコードだけが表示される
- [ ] A〜Eのタブレット表示モードを切り替えられる
- [ ] PIN・QRの重複値や曖昧な一致が誤ったユーザーの打刻につながらない
- [ ] 実際の打刻データが既存の `attendanceItems` に保存される
- [ ] 遅刻・早退機能は後続工程で既存データ形式を確認してから実装する

## 6. PWA・端末別確認

- [ ] Service Workerがv5へ更新される
- [ ] 更新後に旧キャッシュではなく最新のHTML・JavaScriptが読み込まれる
- [ ] iPhoneのSafari/Edgeでインストール・起動できる
- [ ] AndroidのChrome/Edgeでインストール・起動できる
- [ ] PCブラウザで通常表示・ナビゲーションが崩れない
- [ ] 一度オンラインで表示した後、通信を切ってホーム・木材・学習のキャッシュ表示を確認する
- [ ] オフライン中に書き込み操作が実行されないことを確認する

## 7. 公開前の必須確認

- [ ] Firestore Rulesを Emulator で検証する
- [ ] 既存Firestoreデータのフィールド名・型・欠損値を照合する
- [ ] 学習情報の全件バックアップと移行件数を照合する
- [ ] タブレット打刻と認証・Rulesの整合性を確認する
- [ ] `main` へのマージと本番デプロイは、別途明示的な承認を得てから実施する

## 統合時の注意事項

- `tablet.html` は既存運用どおりログイン画面を介さずに使う設計。一方、現在の `firestore.rules` 案は `attendanceItems` の作成にログインを要求するため、そのRulesを適用するとタブレット打刻が拒否される可能性がある。
- この不整合を解消するまでは、Rules案を本番適用しない。タブレットに認証を追加する変更も行わない。既存の本番Rules・タブレット運用を維持したまま、別途許可方式を決めてからRulesを確定する。
- PWA v5は出勤管理の主要HTMLをキャッシュ対象に追加した段階。オフライン起動・更新反映は各端末での実機確認が必要。
