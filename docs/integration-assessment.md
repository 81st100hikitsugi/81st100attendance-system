# 統合システム実装状況

更新日: 2026-11-18  
対象ブランチ: `integration-development`  
対象システム: 出勤管理・学習情報管理・木材管理

## 方針

既存機能と既存データを残し、共通ログイン・共通ホーム・共通ナビゲーションの下に3システムを統合する。細かなUI調整より、主要機能を一つのアプリから利用できることを優先する。

## 実装済み

### 共通基盤
- ログイン後は管理者・一般ユーザーとも `home.html` を開く。
- `students/{uid}.isAdmin === true` を管理者判定に使用。`role` は業務上の役職として独立。
- 共通ヘッダーとスマートフォン向け下部ナビゲーションを用意。
- ホームから出勤・学習・木材の各機能へ移動可能。
- 管理者専用画面は共通の認証ガードで保護。

### 共通ホーム
- 今日の全体作業予定（`dailyWorkPlans`）
- 本人の今日のシフト（既存の `attendanceItems`）
- 本人が予約した木材（`woodItems`）
- 管理者向けショートカット
- Firestoreキャッシュからの読み取りフォールバック

### 出勤管理
- 既存の出勤・退勤、シフト、履歴、通知、ユーザー管理、管理者向けシフト作成を統合版から利用可能。
- 既存の `attendanceItems` を維持し、シフト予定と実打刻を同じコレクション内で区別。
- タブレット打刻のA〜Eの5モードを維持。管理者メニューから起動可能。
- 遅刻・早退は後続工程に延期。

### 学習情報管理
- 共通Firebaseを使う統合画面、教科画面、辞書管理、データ移行画面を用意。
- 旧システムのFirebase設定と移行画面の接続先は、プロジェクトID `learning-info-site` で一致することを確認。
- 移行対象は旧システムで使用している `learningInfos`、`searchDictionary`、`subjectDocuments`。
- IDを維持してコピーし、重複IDがあれば中止。
- JSONバックアップを保存し、保存したファイルを開いて件数・内容を確認した旨をチェックするまでコピーできない。
- 再実行時は移行先の同一ID・同一内容をコピー済みとしてスキップし、同一IDで内容が異なる場合は中止する。これにより、400件単位の途中失敗後も同一内容の既存分を保護しながら再開できる。
- コピー後に移行先を再照合し、欠落・不一致がないことを確認する。
- 旧データは削除しない。実データ移行は未実施。移行処理は再実行時の同一データスキップと移行後照合に対応したが、実Firebaseでの認証・権限・件数・復旧テストは未実施。

### 木材管理
- 一覧、詳細、フィルター、担当者、個別状態更新、一括更新、予約、履歴を実装。
- 長さフィルターのUI（範囲指定／基準値＋許容差）とスクリプトの参照IDを整合。
- 管理者と一般ユーザーの操作範囲を分離。
- まとめ行の数量・代表状態・確認状態を個別木材から更新。
- まとめ行の数量変更は従来仕様に戻した。数量を減らす際は、既存の数量順で個別木材を削除する。共同作業やリーダーによる代理登録を含む現場運用を優先する。
- オフライン時はキャッシュ済みデータの閲覧を優先し、更新操作を停止。

### 検索エンジンへの掲載制御
- リポジトリ内の全HTMLページに `noindex, nofollow` を設定。
- `robots.txt` はクロールを許可し、検索エンジンが各ページのnoindex指定を読み取れるようにする。
- noindexは検索結果への掲載を抑える設定であり、URLを知る人のアクセスを制限する認証機能ではない。検索エンジンの反映には時間がかかり、既存の検索結果が直ちに消える保証はない。

### PWA
- Service Workerは `attendance-system-v13`。
- 共通ホーム、出勤管理主要画面、タブレット、学習、木材、共通モジュールなど30ファイルを事前キャッシュ対象に設定。
- 通知一覧は安全なDOM構築に変更し、オフライン時のFirestoreキャッシュ読み取りに対応。通知作成は管理者認証後に送信ボタンを有効化し、二重送信を抑止。
- Gitブランチのファイルツリー上で、対象30ファイルがすべて存在することを確認。

   Firebase読み書き、iPhone/Androidでの起動、QRカメラ、オフライン動作は未確認。コード確認だけで動作済みとは扱わない。

4. **公開作業**  
   `main` へのマージ、本番Rules適用、本番データ移行、本番デプロイは未実施。明示的な承認なしに実行しない。

## 2026-11-19 共有タブレット認証方式の更新

- 共有タブレットは画面上のログイン操作を不要とする。tablet.html 起動時にFirebase Authenticationの匿名認証をバックグラウンドで行う方式に変更した。
- tabletDevices/{uid} に enabled: true が登録された端末だけが、名簿・打刻データへアクセスできる。未登録端末には端末UIDを表示し、データを読み込まない。
- 匿名認証ユーザーは通常ユーザー向けの signedIn() 判定から除外し、許可リストに登録されたタブレット専用の読み取り・打刻作成権限のみ付与するRules案を追加。
- 初回セットアップにはFirebase Consoleで匿名認証を有効化し、共有タブレットに表示されるUIDをFirestoreの tabletDevices/{uid} に enabled: true で登録する必要がある。
- 通常のスマートフォンからURLを直接開くこと自体は可能だが、未登録端末はデータにアクセスできない。ホーム・共通ナビには引き続きリンクを置かない。
- これは開発ブランチでの実装・Rules案の更新であり、Firebase Consoleの設定、Rulesデプロイ、Emulator・実機テストは未実施。本番には反映していない。登録端末へのデータ公開範囲が広いため、専用最小データ経路を実装するまで本番利用しない。
