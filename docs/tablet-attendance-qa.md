# タブレット打刻・PIN/QR 管理 QA チェックリスト

対象ブランチ: `integration-development`

この文書は、Firebase の開発用環境で実施する手動確認項目です。本番データでは試験しないでください。

## 1. 管理者名簿

- [ ] 管理者でログインし、利用者名簿を開ける
- [ ] 利用者ごとに PIN を入力して保存できる
- [ ] PIN を空欄にして保存できる（PIN方式を使わない利用者）
- [ ] 「QRを発行」で識別値が作られ、QR画像が表示される
- [ ] QR識別値を手入力で変更して保存できる
- [ ] 同じ PIN を別の利用者に保存しようとすると拒否される
- [ ] 同じ QR識別値を別の利用者に保存しようとすると拒否される
- [ ] PIN と QR識別値の間で別利用者と値が衝突する場合も拒否される
- [ ] 同じ画面を開いたまま、先に保存した値との重複も検出される
- [ ] QRコード生成ライブラリを読み込めない場合に、画面上に案内が出る

## 2. タブレットの表示・一覧

- [ ] A〜E の5方式を自由に切り替えられる（Cは状況確認専用）
- [ ] A「全員一覧」に利用者が表示され、名前・役割で検索できる
- [ ] B「シフト対象」に当日の「出勤予定」利用者が表示される
- [ ] 同じ利用者に複数の時間帯のシフトがあっても、一覧には1人として表示される
- [ ] C「出勤状況」に全員の当日の状態と最終打刻が表示される
- [ ] シフトがない日も、全員一覧と出勤状況を利用できる
- [ ] 画面幅が狭い端末でもタブ・ボタン・表が操作できる

## 3. PIN方式

- [ ] 登録済み PIN で正しい利用者が選択される
- [ ] 未登録 PIN では利用者が選択されず、案内が出る
- [ ] PIN 入力を変更すると、以前の選択状態が解除される
- [ ] 複数人に一致する既存データがある場合は、打刻を止めて管理者確認を促す

## 4. QR方式

- [ ] カメラ利用を許可するとカメラが起動する（HTTPS または localhost）
- [ ] 対応ブラウザで登録済み QR を読み取ると正しい利用者が選択される
- [ ] カメラを停止できる
- [ ] 自動読み取り非対応ブラウザでは、QR識別値の手入力で確認できる
- [ ] 未登録・重複した値では打刻されない

## 5. 打刻・履歴

- [ ] A・B・D・E の各方式から出勤を記録できる
- [ ] A・B・D・E の各方式から退勤を記録できる
- [ ] 記録が既存の `attendanceItems` に保存される
- [ ] 保存後にタブレットの当日状態が更新される
- [ ] 同じ利用者の保存処理中に別方式から連続操作しても、同時に二重送信されない
- [ ] 別の時間帯での勤務を想定し、同日に複数回の出勤・退勤記録を作成できる
- [ ] 利用者の打刻履歴が新しい順に表示される
- [ ] シフト予定は打刻と区別され、日付と時間帯が表示される
- [ ] 通信エラー時に失敗メッセージが表示される

## 6. 既知の確認事項

- 実際の Firebase 接続、Firestore の読み書き、QRカメラ読み取りは、このコード確認だけでは検証できていません。
- QRカメラの自動読み取りはブラウザの `BarcodeDetector` 対応状況に依存します。非対応時は手入力を利用します。
- PIN/QRの重複チェックは管理画面での保存時とタブレット側の照合時に行います。複数管理者が同時に編集するケースは、実環境で別途確認が必要です。
- 共有タブレットは `tablet.html` を直接開いて利用し、ログイン画面は設けません。
- 通常のログイン後ホーム・共通ナビにはタブレットへのリンクを設けません。タブレット画面は共有端末専用の独立ページとして扱います。
- 通常のスマートフォンからタブレットページへの導線は不要です。ただし、URLを直接知っている端末からのアクセスをページ単体で完全に禁止することはできません。
- 開発用 `firestore.rules` には匿名認証＋端末UID許可リスト方式を実装しています。Firebase Consoleで匿名認証を有効化し、端末UIDを登録したうえで、Emulatorまたはテスト用Firebaseで許可・拒否テストを行う必要があります。本番Rulesには適用していません。

## 7. 共有タブレットの端末登録（匿名認証）

タブレット画面にログインフォームはありません。Firebase Authentication の匿名認証をバックグラウンドで利用し、端末UIDをFirestoreの許可リストで照合します。

初回セットアップ（開発用Firebaseで実施）:

1. Firebase Consoleで対象プロジェクトの Authentication → Sign-in method を開き、匿名（Anonymous）プロバイダを有効にする。
2. 共有タブレットのブラウザで tablet.html を開く。
3. 未登録と表示された場合、画面に表示された端末ID（匿名認証UID）を控える。
4. Firestoreの tabletDevices/{端末ID} にドキュメントを作成し、enabled: true（boolean）を設定する。
5. タブレット画面を再読み込みし、名簿・当日記録が読み込まれることを確認する。

- [ ] 匿名認証が有効な状態で端末UIDが発行される
- [ ] 未登録端末は名簿・打刻データを読み書きできない
- [ ] tabletDevices/{uid}.enabled == true の登録端末だけが画面を利用できる
- [ ] 登録済み端末でA〜Eの画面が開き、A・B・D・Eで打刻できる
- [ ] enabled を false にすると、次回の読み込みから利用できない
- [ ] ブラウザのサイトデータ消去などで匿名UIDが変わった場合、新しいUIDを再登録する

注意:
- 匿名認証は画面上のログイン操作を不要にするための仕組みです。端末を登録するまではデータアクセスできません。
- 現在のRules案では登録端末に `students` 全文書と `attendanceItems` の読み取り権限が付与されます。画面は当日分だけを取得しますが、Rules自体は日付・フィールドを制限しません。またPIN/QRはクライアント側で照合するため、全利用者分の識別情報が端末に渡ります。この状態では本番運用しないでください。
- 現在の firestore.rules は開発ブランチ上の案です。Firebase Consoleへの適用・デプロイは行っていません。本番へ適用する前にEmulatorまたはテスト用Firebaseで許可・拒否テストが必要です。


## 8. 本番運用前のセキュリティ必須対応

- [ ] `students` 全文書をタブレットへ返さず、必要最小限の名簿データだけを返す専用経路を実装する
- [ ] `attendanceItems` を直接読ませず、当日表示に必要な最小項目だけを返す専用経路を実装する
- [ ] PIN/QRの照合をサーバー側で行い、全利用者のPIN/QR値をタブレットへ配布しない
- [ ] Emulatorまたはテスト用Firebaseで、登録端末・未登録端末・通常ユーザーの許可／拒否を検証する

上記が完了するまでは匿名認証の有効化、端末登録、本番Rules適用を行わない。
